# 小红书爬取风控规避策略（2026-09-10）

> 目标：降低信息提取时的访问频率与行为规律性，尽可能规避平台风控。原则：**不砍功能、不阻塞登录预热、全部可配置**。

## 1. 已落地的措施（local_site_crawler_service.py）

### 1.1 请求节流（频率维度）

| 场景 | 旧值 | 新值（默认） | 配置项 |
|---|---|---|---|
| 详情页访问后间隔 | —（无） | **3–6s**，每 `crawl_burst_size=8` 页后长休息 **15–30s** | `CRAWL_DELAY_MIN/MAX`、`CRAWL_BURST_SIZE`、`CRAWL_BURST_REST_MIN/MAX` |
| 搜索页加载停留 | 2–3s | **4–8s** | `CRAWL_SEARCH_DELAY_MIN/MAX` |
| 多关键词之间冷却 | —（无） | **8–15s** | `CRAWL_KEYWORD_COOLDOWN_MIN/MAX` |
| 详情页打开后阅读停留 | 1.0–1.8s | **2.0–4.0s**（人类至少看几秒） | 硬编码 |
| 滚动停顿 | 0.8–1.2s | **1.5–3.0s** | 硬编码 |
| 首页登录检查停留 | 固定 2s | **2.0–3.5s** | 硬编码 |

行为逻辑：间隔全部随机化（`random.uniform`），与目标采集数解耦——**每次详情页访问后必节流，无论该笔记是否有效**，避免"无效页快刷"暴露机器节奏。连续 8 页插一次 15-30s 长休息，把"匀速扫荡"变成"间歇阅读"。

### 1.2 浏览器指纹（特征维度）

- **viewport 随机化**：每次爬取从 `{1366,1440,1536,1600,1920}×{768,864,900,1000,1080}` 随机组合（旧版固定 1440×900 是典型爬虫指纹）
- **UA 更新**：Chrome/124 → Chrome/131（旧 UA 已偏离当前主流版本，易被打分）
- **locale=zh-CN、timezone=Asia/Shanghai** 显式声明，与中文环境一致
- 保留 `--disable-blink-features=AutomationControlled`（抹除 `navigator.webdriver`）

### 1.3 未做与理由

- **代理 IP 轮换**：单账号+住宅 IP 场景下频繁换 IP 反而更可疑（跨地域跳变）；如需多账号矩阵再引入。
- **请求拦截/资源屏蔽**：屏蔽图片可提速但改变请求指纹（缺失的图片请求本身是特征），收益风险比差。
- **鼠标轨迹模拟**：Playwright 层面成本高，且小红书风控主要看请求节奏与指纹，暂缓。

## 2. 频率上限估算（默认配置）

单关键词、target=5：登录检查 ~3s + 搜索 ~6s + 滚动 ~4.5s + 5 详情页 ×(3s 阅读+4.5s 间隔) ≈ **50s**（旧版 ~25s）。多关键词每切换一次 +8-15s。长跑场景（scheduler 定时 crawl）建议把 `CRAWL_DELAY_MIN/MAX` 进一步调大而非调小。

## 3. 已知残余风险

- 单 storage_state 长期复用，cookie 指纹固定——这是"登录态复用"的必然代价，登录态失效时 `_ensure_logged_in` 会检测重定向并快速失败（P2-b），用户重新预热即可。
- headless 模式默认开启（`crawl_headless`），若风控加强可置 `CRAWL_HEADLESS=false` 用有头窗口爬取（行为特征更接近真人）。
- 本文档措施降低风险但不保证零风险；请遵守平台条款，仅采集公开数据、控制总量与频率。
